# Source, snapshot and routing notes

Primary source: https://github.com/thecolab-ai/.skills
Authentication: none
Last verified: 2026-10-08

The seed is the supplied Auckland CivicTech Hackathon `akl-catalogue-v4.json`
export, reviewed on 7–8 October 2026 for the 16 October event. The original
export is an external build input and is not needed at runtime. Its SHA-256 is
recorded in the gzip metadata, along with input, retained and excluded counts.
The GitHub URL identifies the distribution repository, not an upstream API
for the assessment spreadsheet. No public download URL for the export was
supplied, so refreshes require another local JSON export.

The build removes 63 rows marked `Duplicate of` and seven with agent check
`Broken`, leaving 3,168 sources. It keeps 278 `Not data` rows and flags them;
226 `Could not verify` rows and three with no agent check remain visible.
It does not merge different sources just because they share an owner or URL.
Eleven rows contain non-braced credential-like URL query values, including
some placeholder strings. The build replaces these with `{credential}` and
flags the rows `credential_redacted: true`; no such value is shipped or sent
by the checker. The non-authentication Taginfo `key` parameter is retained.
Names, dates and record counts are preserved even when the reviewer noted
corrections in the long notes, which are intentionally omitted. Read caveats,
fetch the dataset and confirm its current metadata before relying on a claim.

all build columns, plus real duplicate, broken and not-data cases.

retrieval time and snapshot latest-data statements. The fixtures retain only

The contract sentinel is synthetic repository-policy metadata.

## Mapping maintenance

`skill-map.json` contains 78 ordered rules covering 31 existing skills and
seven planned engines. Existing skill names, source URLs and auth modes were
read from their `skills/<name>/SKILL.md` files, then restricted to known
capabilities. The rule matches hosts and optional path/ID fragments against
the same direct or landing URL. Optional name and NZ-scope restrictions also
apply. Matching rules are returned in order, deduplicated by skill name.

Do not route every dataset on a shared host to a specialist: Zenodo is limited
to SeaRise, CKAN schools use a subject restriction, and ArcGIS rules use
organisation IDs. `related` mappings require reading that skill's commands;
`catalogue` mappings discover metadata and do not promise source retrieval.
Planned ArcGIS organisation/host pairs come from actual NZ-scoped seed rows,
but this is a routing suggestion, not the new engine's fetch allowlist.
Confirm supported organisations once that engine is installed. In particular,
`wcc-arcgis-nz` stays restricted to its Wellington infrastructure.

The planned engines are `nz-arcgis`, `nz-stac`, `nz-ogc-records`, `gtfs-nz`,
`nz-recycling-locator` and `akl-rainfall`. They are explicitly
marked `planned` even if another installation has since added them. Update
these statuses and rules after reviewing those skills. Unmatched sources use
an empty `fetch_skills` list, never an invented fetch command.

## Live check limitations

Live probes inspect HTTP reachability and a bounded body sample only. A 200
response can be a landing page, a login page or a restricted dataset. Common
browser challenges and complete JSON error objects are detected; other semantic
failures or errors beyond the first 64 KiB may not be. `sample_may_be_truncated`
makes that bound visible. Last-Modified headers do not replace the snapshot's
source-stated latest-data field. The CLI does not persist probe responses or
revise grades, checks, counts or mapped-skill status based on one probe.

HTTP requests and redirects use a 10-second socket timeout, with Python's
standard redirect limit. Hostnames are restricted to the shipped exact host
allowlist and checked for public IP addresses before requests. DNS resolution
and several redirects can make total elapsed time exceed ten seconds. Requests
use standard urllib routing and no custom authentication, browser or proxy
credential handling. A new export can change the host inventory: sync the
frontmatter's outbound domains to the rebuilt index and run validation.
